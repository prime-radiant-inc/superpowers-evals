## Fix and qualification

Pi 0.80.7 converts its working directory into one session-directory component
unless a session directory is configured. The original campaign produced
291/290-byte components and failed with `ENAMETOOLONG` before accepting input.

Quorum now writes Pi's native `settings.sessionDir` to the isolated
`<home>/.pi/agent/sessions` directory for API-key and OAuth provisioning. The
real working directory and session-header cwd are preserved. Main sessions now
live directly under the capture root; recursive capture still includes nested
histories and child sessions. This is an explicit setup change applied equally
to both follow-up arms. It does not change the remembered native histories or
the Superpowers skill packages.

The two provisioning regression assertions failed before the change and passed
afterward. The focused Pi/launcher/history suites passed 85 tests. An offline
probe in the exact original Linux image reproduced the original crash at a
337-byte working path. With the fix, both auth modes created a native session
under the capture root and preserved the full cwd. The real generated launcher
also answered an RPC `get_state` at that path. Networking was disabled, only
fake credentials were supplied, and no model prompt was sent. Independent code
review found no actionable issues. Full `bun run check` passed (3,612 runner
tests, 144 dashboard tests, 15 platform skips; lint/typecheck clean), and
`bun run quorum check` passed.

## ATIF timestamp repair

Quorum now preserves valid Pi record timestamps on user and assistant ATIF
steps, including every step split from one message's tool calls and the final
answer. Session/model metadata does not become a conversation timestamp, and
attaching a tool result does not overwrite its call's timestamp. Missing or
malformed record timestamps remain absent. Pi's live timing probe now uses the
ATIF normalizer, sharing the conversion used for final capture.

The regression test reproduced the original mismatch through the real native
fixture, capture, merge, saved `trajectory.json`, and campaign timing readers.
Before the fix, three timestamp assertions failed; after the fix, all 86 focused
normalizer, sensor, and capture tests passed. Independent review found no issues.
Full `bun run check` also passed: lint and typecheck, 3,618 runner tests and
144 dashboard tests, with 15 platform skips and no failures.

Both saved live logs were also reprocessed through production capture into
private output directories. The resulting ATIF contains timestamps on all 18
before steps and all 19 after steps. Removing only those added fields gives an
object identical to each original published trajectory: messages, tool calls,
results, order, and usage are preserved. Both the live probe and the final ATIF
reader now return the original opening-prompt times, 4.686 seconds apart, and
the timing audit reports no disagreement or exclusion change.

The reproducible check and hash receipts are retained under
`pi-followup/timestamp-fix/{verify.ts,verification.json}` in the private evidence
root above. Original logs and campaign outputs are unchanged. This offline
verification fixes and exercises the reporting path without another paid run;
it does not replace the original campaign report or alter its frozen verdict.
