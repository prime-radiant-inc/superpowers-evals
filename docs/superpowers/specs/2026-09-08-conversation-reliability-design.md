## Verification and gates

Offline tests exercise real publication, real generated launchers and actual SDK request serialization against local scripted responses. Existing negative live evidence is the semantic baseline for prompt-only changes; wording assertions do not prove instruction-following. Each code task receives independent spec/quality review; the integrated change receives one final review and one combined correction wave if needed. Run required repository checks and actual paired CLI tests on the selected runtime.

Root owns all appliance operations through Tailscale and the existing helper, source preparation, provider calls, accounting and cancellation. Recheck installed sources, ownership and image before use. Use fresh registered identities; do not resume or replace the previous night's failed attempts. Continue direct integration to main without PRs and canonical helper deployment only for pieces whose applicable gates pass. Failed semantic candidates remain unpromoted even if their unit tests pass.

Fresh provider work is bounded to **$20 observed usage**, allocated **$8 retained assessment** and **$12 fresh conversations**, without transferring allocations. Missing/unpriced required usage or an instrument failure stops the affected stream; reconcile ownership before proceeding with independent work. An in-flight call can exceed the threshold; these are stopping allocations, not billing caps. Preserve unknown billing rather than reporting zero.

Before calls, commit the exact case selection, source pins, expectations and order. Retained assessment: at most **24 calls**, one frozen candidate, two repetitions per selected case, known cases before constructed controls, no replacement cases or second prompt candidate. Each call has a two-minute external bound and the stage a 90-minute window. Stop on invalid output or a semantic gate failure; no calls solely to obtain a favorable replacement result. The operator remains experiment-specific and uses existing Gauntlet assessment, scoped credentials, shared lease and ordinary artifacts.

Fresh conversations: at most **eight attempts**, ten-minute conversations, 900-second attempt bounds, global cap four. Start with Pi pricing and review qualification; stop Pi admission on lifecycle/capture/publication failure. Use the remaining slots for targeted design/feedback conversations on established harnesses, with candidate assessor only after its retained gate passes. Freeze exact cells before launching. Audit simulated-user adherence and delivery separately, recording independent judgments before revealing official grades. Completed bad work is useful signal, but a driver violation cannot become an unqualified model-comparison result.

The live-work window is at most four hours from the first fresh provider call, including cleanup headroom. No new call starts unless its bound and cleanup fit. This is a new daytime increment; the closed overnight allocation, cutoff and paused heartbeat remain closed. No recurring automation or sleep inhibitor is needed for this active task.

## Exit condition

Report each piece independently: published failure evidence with available usage; installed Pi startup/capture and bounded qualification; accurate provider error feedback; simulated-user adherence on the selected cases; and valid, correctly reasoned assessor results against the frozen cases. Record negative results with the same visibility as successful ones. Broader harness coverage, bulk scenario migration, higher-capacity studies and architectural replacement remain outside this increment.
